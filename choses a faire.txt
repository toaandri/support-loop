SUPPORT-LOOP
AI CUSTOMER SUPPORT AGENT
==========================

Projet d'etude / autodidacte pour GitHub

Nom du repository
-----------------
support-loop

Description courte GitHub
-------------------------
AI customer support agent with RAG, automated tool execution, human handoff, and a feedback-driven learning loop, powered by n8n.

Description generale
--------------------
SupportLoop est un systeme de support client pilote par un agent IA et orchestre par n8n.

L'objectif est de construire un systeme capable de :
- recevoir des demandes clients ;
- comprendre et classifier les demandes ;
- rechercher les informations pertinentes dans une base de connaissances ;
- interroger les donnees de l'entreprise ;
- utiliser des outils/API pour effectuer certaines actions ;
- repondre automatiquement lorsque la confiance est suffisante ;
- transferer la conversation a un humain lorsque l'agent n'est pas suffisamment certain ;
- recuperer la reponse/resolution humaine ;
- transformer cette resolution en nouvelle connaissance ;
- faire valider cette connaissance avant son activation ;
- reutiliser cette connaissance dans des cas similaires futurs.

IMPORTANT : le systeme ne doit pas re-entrainer automatiquement le modele LLM apres chaque intervention humaine. Le projet utilise plutot une boucle d'amelioration controlee basee sur la connaissance, le RAG, les corrections humaines et la validation.

CONCEPT CENTRAL : LE LEARNING LOOP
-----------------------------------
IA
  -> ne sait pas / confiance faible
  -> humain
  -> reponse humaine
  -> extraction d'une connaissance ou d'une regle
  -> validation humaine/admin
  -> ajout a la Knowledge Base
  -> utilisation par l'IA dans les futurs cas similaires

Exemple :
Client : "Je peux annuler ma commande alors qu'elle est deja expediee ?"

L'agent estime :
Confidence = 61%
Threshold = 85%

Le cas est transfere a un humain.

L'humain repond :
"Une commande deja expediee ne peut pas etre annulee. Le client doit attendre la livraison puis demander un retour sous 14 jours."

Le systeme peut extraire une connaissance structuree :

{
  "intent": "cancel_shipped_order",
  "condition": "order_status = shipped",
  "resolution": "return_after_delivery",
  "return_period": "14 days",
  "approved": false
}

Workflow de connaissance :
NEW -> REVIEW -> APPROVED -> ACTIVE

Lorsqu'un autre client pose une question similaire, l'agent recherche cette connaissance et peut repondre automatiquement si son niveau de confiance est suffisant.

RAG / KNOWLEDGE BASE

Exemple de documents :

knowledge/
  delivery.pdf
  refund-policy.pdf
  warranty.pdf
  faq.md
  products/
  procedures/

Pipeline d'ingestion :

Documents
  -> extraction du texte
  -> nettoyage
  -> chunking
  -> embeddings
  -> PostgreSQL + pgvector

Lors d'une demande :

Question client
  -> embedding
  -> recherche vectorielle
  -> documents/connaissances pertinents
  -> agent IA
  -> reponse

L'agent doit privilegier les informations provenant de la Knowledge Base et eviter d'inventer des politiques ou procedures.

AGENT IA ET TOOLS
-----------------

L'agent peut disposer de tools tels que :

search_customer()
get_customer_orders()
get_order()
get_order_status()
search_product()
check_stock()
create_ticket()
update_ticket()
create_refund_request()
send_email()
notify_human()
search_knowledge_base()

Exemple :

Client :
"Ou est ma commande ?"

Agent :
  -> identifie le client
  -> get_customer()
  -> get_order()
  -> get_tracking()
  -> genere la reponse
  -> repond au client

L'agent ne doit pas avoir un acces illimite aux outils. Les actions sensibles doivent etre protegees par des regles, des permissions et/ou une validation humaine.

HUMAN-IN-THE-LOOP
-----------------

Le systeme doit prevoir plusieurs raisons d'escalade :

- confiance faible ;
- information absente de la Knowledge Base ;
- demande ambiguë ;
- action sensible ;
- remboursement important ;
- suppression de compte ;
- probleme juridique ;
- client tres mecontent ;
- erreur d'outil/API ;
- demande hors perimetre.

Exemples :

Question simple -> IA
Confiance faible -> Humain
Petit remboursement -> eventuellement automatique selon politique
Gros remboursement -> Humain
Suppression de compte -> Humain
Reclamation juridique -> Humain

Lorsqu'une conversation est transferee, l'humain doit recevoir le contexte utile :
- message du client ;
- historique ;
- informations client pertinentes ;
- resultat des recherches ;
- actions deja effectuees ;
- raison de l'escalade ;
- niveau de confiance.

LEARNING PIPELINE
-----------------

Lorsqu'un humain intervient :

Conversation
  -> reponse humaine
  -> analyse/extraction IA
  -> proposition de nouvelle connaissance
  -> validation admin
  -> stockage
  -> indexation vectorielle si necessaire
  -> utilisation future

Ne jamais considerer automatiquement toute reponse humaine comme une verite absolue.

Exemple de pipeline :

Human response
  -> AI extracts rule
  -> NEW
  -> REVIEW
  -> Admin APPROVES / REJECTS / EDITS
  -> ACTIVE

Le systeme peut aussi enregistrer les corrections de l'humain lorsque l'IA avait donne une mauvaise reponse.

Exemple :

Question :
"Puis-je retourner ce produit ?"

Reponse IA :
"30 jours"

Correction humaine :
"14 jours"

Le systeme conserve :
- question ;
- reponse IA ;
- correction humaine ;
- reponse finale validee ;
- connaissance/regle associee.

Ces donnees peuvent ensuite servir a :
- ameliorer le RAG ;
- ameliorer les prompts ;
- construire un jeu d'evaluation ;
- mesurer les erreurs ;
- preparer eventuellement un futur fine-tuning.

SECURITE ET GARDE-FOUS
----------------------

Le projet doit considerer l'IA comme non infaillible.

Principes :
- ne pas inventer une politique inexistante ;
- ne pas executer des actions sensibles sans autorisation ;
- appliquer des seuils de confiance avec prudence ;
- journaliser les actions de l'agent ;
- limiter les permissions des tools ;
- proteger les secrets/API keys ;
- ne pas exposer les donnees inutiles au LLM ;
- verifier les permissions utilisateur ;
- conserver une trace des validations humaines ;
- prevoir retry/timeouts pour les APIs ;
- gerer les erreurs n8n et les erreurs LLM.
